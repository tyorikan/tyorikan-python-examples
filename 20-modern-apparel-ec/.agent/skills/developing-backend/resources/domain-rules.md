## 価格

- すべての商品は `base_price`（JPY、正の整数）を持つ。
- 表示価格は **税込み**（消費税 10%）。
- 割引タイプ: パーセンテージ（例: 20% OFF）、固定額（例: 500円 OFF）。
- 割引でマイナス価格にはできない。
- `current_price = min(base_price, active_campaign_price)`。
- フラッシュセールには `start_time` と `end_time` が必須。チェックアウト時に検証する。
- セッション中にキャンペーンが終了した場合、カート追加時点の価格を尊重する（スナップショット）。
- 税金の端数処理: **切り捨て（FLOOR）**。

## 在庫

- カート追加時に在庫を **確認**。
- チェックアウト開始時に在庫を **仮引当**（15 分間の一時ホールド）。
- 決済成功時に在庫を **確定**。
- 表示: `> 5` → 「在庫あり」、`<= 5` → 「残り X 個！」、`== 0` → 「売り切れ」。
- 検索結果: 結果整合性（Eventual consistency）OK。カートの書き込み: 強整合性が必須。
- フラッシュセールの競合: 在庫引当パターン（Redis + Spanner）を使う。

## チェックアウト

- **カート**: 揮発性、書き込み頻度が高い。ログイン時にゲストカート（Cookie）をユーザーカート（DB）にマージ。
- カート表示のたびに在庫と価格を再検証する。
- ログインユーザーのカート保持期間: 30 日。
- **注文処理**（4 フェーズ、単一の同期リクエストで行わない）:
  1. 引当 → 在庫をロック
  2. 認証 → 決済ゲートウェイ（Stripe/GMO）に問い合わせ
  3. 確定 → カートを不変の注文レコードに変換
  4. 確認 → メール送信（非同期、Saga パターン）
- **決済**: PCI-DSS 準拠（トークン化のみ）。すべての決済 API は `Idempotency-Key` を受け入れる。
- **送料**: 5,000 円以上 → 無料。5,000 円未満 → 一律 550 円。
- **合計計算**: `sum(item.price * qty) + shipping - coupon + tax`。
- 決済タイムアウト: リトライ前に決済状態を問い合わせる。
- 最後の 1 個を同時購入: 片方が成功し、もう片方は「在庫切れ」で穏やかに失敗する。

## 顧客

- **認証（AuthN）**: OIDC（Google, Apple, Email/Password）。JWT アクセストークン（15 分）+ 不透明リフレッシュトークン（30 日、無効化可能）。
- **認可（AuthZ）**: RBAC — `GUEST`、`MEMBER`、`ADMIN`、`SUPPORT`。リソースオーナーシップ: `user_id == current_user.id`。
- **プロフィール**: アドレス帳（1:N）、決済方法（1:N、トークン化済み）、設定。
- **GDPR/APPI**: 「忘れられる権利」→ PII を物理削除し、取引履歴は匿名化して保持する。データエクスポート機能を提供する。
