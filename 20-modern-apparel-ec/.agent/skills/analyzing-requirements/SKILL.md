# 要件分析

## 分析チェックリスト

すべての要件に対して、以下をカバーする技術仕様書を作成する:

1. **正常系（Happy path）**: 理想的なフロー。
2. **異常系（Unhappy paths）**:
   - ネットワークタイムアウトが発生したら？
   - 不正な入力が来たら？
   - 権限がなかったら？
   - レート制限/リソース枯渇が起きたら？
3. **データライフサイクル**:
   - データはどこで生まれるか？
   - 誰が所有するか？
   - いつアーカイブ/削除されるか？

## アウトプットの構成

### 明確にすべき不明点
コーディング前に回答が必要な明示的な質問を列挙する。
- 例: 「レビュー本文の最大文字数は？」「ユーザー名に絵文字は使えるか？」

### 非機能要件
- **レイテンシ**: 例: 「200ms 以内に応答すること」
- **スケール**: 例: 「毎分 1000 件のレビュー投稿をサポートすること」
